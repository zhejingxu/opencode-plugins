I built a version of this in my fork. It may help answer the questions in the design proposal above:

- It pins a whole Q&A turn (the user message plus its response), not a text selection. The pin button is on both the user message and the response.
- Pins are stored client-side, per session, in the existing layout store. No server changes.
- Pinned turns open in a resizable panel left of the timeline, with one tab per pinned turn, jump to message, unpin, and clear all. I chose a panel over a header toggle so a pinned answer stays readable while the chat continues.
- The icon is a `pin` / `pin-active` pair.

Patch: https://github.com/zhejingxu/opencode-plugins/blob/main/patches/0002-feat-app-pin-Q-A-turns-to-a-left-side-panel.patch

I'd rather ship this as a GUI plugin, but it needs the extension point I asked for in #61385.
